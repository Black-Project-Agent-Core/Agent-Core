Make Native provider/key rotation auditable without changing its policy. The SQLite provider state now reports, for every selection, how many sibling keys were configured, eligible and skipped by reason (invalid, disabled, rate-limit, quota, model-unavailable, cooldown, readiness, context, transient), and a route is described as "all limit/quota" only when every configured key is a rate-limit or quota case; any other mixture is reported as mixed. Each attempt, failure, success, skip and attempt-budget pause is emitted as a secret-free `provider.route.decision` turn event carrying task, turn and request identifiers, the provider/model and key alias moved from and to, failure class and scope, retry time, attempt window and total, and the transition reason (initial, keep, sibling-key, provider-switch). The route trail is kept in the provider-wait checkpoint so the continuation that resumes an attempt-budget pause through the existing chat resume still shows why the previous window ended. Sticky cursor, sibling-first order, pinned models and mutating-tool replay protection are unchanged. Routing design adapts the account-versus-request separation from 9Router (MIT) without importing its code.
