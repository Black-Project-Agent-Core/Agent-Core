Untrusted content, credentials and OAuth registration. A new text cleaner (`src/security/untrusted-text.ts`) drops zero-width, bidi-override, soft-hyphen, tag and variation-selector characters, blank-looking letters and runs of stacked combining marks, while keeping the Persian half-space, emoji joiners and emoji presentation; it now cleans plugin Skill descriptions (a strict-valid Skill whose description hides such characters goes through the adapter and the change is reported), the text of every recalled note and graph label in the Native knowledge packet, and OAuth client names. The Native system prompt says that tool results, web pages, files, recalled notes and plugin text are data, and that an action whose target comes only from such text is shown to the user first (a read-only lookup within the granted scope and a target the user named are exempt; an unattended task records an observation instead). Secret redaction also recognises labelled-less keys (OpenRouter, Anthropic and other `sk-` keys, GitHub, AWS, Google, Slack, JWT, URL credentials and private key blocks), and one name check now treats editor and Windows copies of credential files (`.env~`, `id_rsa.bak`, `server.pem.old`, `.env:stream`) like the originals when checkpointing. `/oauth/register`, which runs before any authentication, is limited to 20 registrations a minute and to 50 clients that never authorized; a client that never authorized is dropped after a day, a used client never is, and the response is `429` with `Retry-After`. The Memory safety scan refuses a Luhn-valid card number beside a card keyword, and `NIK`/`KTP`, SSN and passport numbers beside their keyword, except the published payment-provider test numbers.
