File and git integrity on the Windows host. The edit tool now decodes a file strictly: a file that is not valid UTF-8 (for example Windows-1252) is refused instead of being edited lossily and written back with its unreadable bytes destroyed, and UTF-16 (LE and BE) files are decoded. An existing UTF-8 BOM or UTF-16 encoding is kept when the write tools rewrite or append, without doubling the BOM. Every read-only git call that Agent Core makes (change review, graph observability, Memory identity and provenance, workspace ref and ignore listing, task changes) now goes through one hardened helper: no optional locks, no fsmonitor daemon, no stat-only index refresh (a plain `git diff` could rewrite `.git/index`), unquoted non-ASCII paths, fixed `a/` `b/` prefixes whatever `diff.mnemonicPrefix` says, and a stable locale; change review therefore no longer loses hunks for non-ASCII paths. Task changes ignores submodules, shares the task deadline across its git calls and parses file names that contain a tab. The workspace fingerprint reports when path evidence was cut, refuses to call missing paths resolved from a cut list, classifies lockfiles and generated sources as noise and no longer touches the index. Restoring a checkpoint now reads every restored file back before reporting success and rolls back otherwise, and hunk lines are cut without splitting a surrogate pair.
