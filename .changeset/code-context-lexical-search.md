Add `code_orient` action `context`: lexical (BM25 over identifier tokens) search over bounded line windows of the workspace source. Returns line ranges and masked, bounded snippets re-read from disk. A hit whose file changed since indexing triggers one rebuild and is never returned with the old range. A new, renamed, or deleted file is found on the next query, without waiting for the cache TTL. Files are masked before indexing: compound secret names, backtick and typed assignments, and PEM key blocks that span windows. When the file list is cut, src, tests, and scripts are indexed before docs, and the cut is reported. Refuses a root inside a denied folder or above the repository, and a ref the working tree is not at. Reuses the memory identifier tokenizer and secret masker, excludes runtime, secrets, protected folders, backups, junctions that leave the root, and key, env, or credential files, and reports skipped files by name. Telemetry and controller bookkeeping match the provider tools; context results are logged as metadata only. No embeddings, no network, no persisted state; the tool count is unchanged. First step of the Code Context Engine study (`docs/proposals/Code-Context-Engine-Steal-Use-Integration-Plan.md`).
