# Agent Core 1.6.0 — Windows x64

Release date: 28 October 2026 (Asia/Bangkok). This version closes the Claude ecosystem donor work, packages UP-01 to UP-14 of [the proposal and its ledger](../proposals/Claude-Ecosystem-Donor-Proposals.md), which were released one by one as 1.0.0 to 1.5.14. Per-change detail is in the [changelog](../../CHANGELOG.md) and in `docs/CODEBASE.md`.

## Current release

- **Truthful scanner and plugin adapter.** The `changed_source` security scanner reports what it actually scanned and with which limits. The Claude plugin adapter reports what real plugins contain and normalizes unsafe descriptions.
- **Host safety on Windows.** The process tool refuses an invalid PID, Agent Core's own process and its direct parent. A narrow guard refuses catastrophic deletes. File reads decode UTF-8 strictly and recognize UTF-16, and git reads reject option-like references.
- **Native loop reliability.** The loop reads why a reply ended, never runs a tool call that was cut off, and names each tool failure by cause. Provider errors are classified from the HTTP status first.
- **Text from outside is data.** Tool results, web pages, files, recalled notes and plugin text are treated as data. Invisible and bidirectional control characters are removed from labels built from them. Key-shaped secrets are redacted without a label, credential file name variants are recognized, and the Memory safety scan flags personal identifiers.
- **OAuth registration limits.** Dynamic client registration is limited to 20 per minute for the process and 50 clients that have never authorized (24 hours), answered with `429` and `Retry-After`.
- **Measure before trimming.** `scripts/verify/agents-md-audit.mjs` reports the bytes of the always-loaded instructions and the tool manifest. No contract wording was changed.
- **Evidence tools.** `scripts/verify/skill-pack-lint.mjs` (baseline, trigger overlap), `scripts/verify/test-run-evidence.mjs` (a verdict computed from counts, with a built-in negative control), `scripts/inspect/work-receipt.mjs` (counts from the local Activity Tracker, `?` for unreadable values) and the explicit `scripts/research/skill-upstream-drift.mjs`.
- **Tracker fixes.** Skill outcomes are recorded under a valid feature id, a rejected outcome no longer throws into its caller, and an unreadable journal is no longer reported as empty.
- **Skills.** Fourteen reference deltas for ten existing Skills and two Skills built as sources (`windows-powershell-host`, `skill-authoring`) ship as sources. A fresh release still seeds only the four Skills listed in the README; every promotion or activation remains an owner decision.
- **Repository and docs.** An agent-behavior issue form, `.gitattributes` protection of Skill bytes (`runtime/skills/** -text`), a Cloudflare probe table, a `servers.json` guide for extra language servers, the "one product, two registrations" rule, a UI theme contrast test, and `link.txt` removed from the repository.

## What this release does not claim

- No speed or quality benchmark was run, and none of the new Skill references has a measured benefit.
- Not done: relocation of pack files outside `references/` (owner decision D5), routing-eval based Non-triggers rewrites, the wider test matrix for `task-changes`, fingerprint and scanner, and the reference-only items in the proposal. Open owner decisions are D2, D3, D8 and D9, plus the status of the Skill proposals and ten staged Skill candidates.
- Tiered workspace instructions for Native (UP-12) were recorded and not implemented.

## Source qualification

- Verification was targeted per package: each package lists its test files and results in the proposal ledger and in `docs/CODEBASE.md`. The full root suite was **not** run on this machine, which is slow; long memory, checkpoint and RDC runs were stopped after 35 minutes and only the files that touch changed paths were run. Two tests are known to be load-sensitive (`semantic-ide-provisioning` needs a longer timeout, `task-changes` can fail with `ECONNRESET` under parallel load) and pass when run alone.
- `npm run build` exited 0 with path policy and project structure PASS before packaging. The UI type check passed.
- After the 1.5.6 restart the resident reported its version with `stale=false`; `kill_process` refused PID 0 and Agent Core's own PID, and `/oauth/register` returned 201 with hidden characters removed from the client name.
- Windows package acceptance in an isolated folder (extraction, health, hashes, launcher version) is performed after packaging and recorded outside the archive.

## Package and installation

The ZIP, its manifests and `SHA256SUMS.txt` are produced by `npm run release:package`; nothing is published by that command. Installation steps are unchanged from [0.15.0](0.15.0.md): verify the checksum, extract the full archive to a writable folder, initialize Memory only for a new installation, then launch `Agent Core.exe`. Do not extract over a running installation.
