## Bagian C — Ditolak / tidak relevan

- C-1 Mesin tier dan hold `sec-default` sebagai runtime (`held-verdict/*`, `next.to`, `tool.check` dijalankan dua kali, pin `env.set`, `plugin.register` refuse, name-folding server MCP organisasi). Bukti baru yang diperiksa: tidak ada yang berubah dalam hal itu; yang diambil hanyalah prinsip (MOD-03, MOD-17). - C-4 Seluruh UI pane `diff` (`views` 172, `pane-state` 46, `names`, `record`, `backend`, `todos`, `pane-toggle`, `open-outcome`): render terminal Ink; Agent Core memakai React/WebView. Panel perubahan Agent Core sudah ada. Satu-satunya yang diambil: MOD-13 dan MOD-19.

## Bagian D — Pola lintas-unit dan pertanyaan terbuka

Pola yang berulang dan layak jadi standar Agent Core (semuanya tanpa menambah teks selalu-dimuat):

1. Asal dipasang oleh host, bukan oleh penulis teks, dan himpunannya tertutup. Nilai tak dikenal jatuh ke kategori paling tidak tepercaya (`unclassified`, "bukan sdk"). Dipakai di `PromptOrigin`, `McpServerProvenance`, `SessionAppendOrigin`, `Origin` rantai hook (→ MOD-07).
2. Verdict yang melonggarkan hanya sah bila dibuktikan; yang tak dapat diverifikasi menjadi penolakan; parsing opsi asimetris (longgar = literal persis, ketat = apa saja selain false). Penjelasan "siapa yang menahan" disampaikan sekali per jenis (→ MOD-03, MOD-17).
3. Data diklasifikasikan oleh taksonomi tertutup yang dapat dicabangkan (`ContextCategoryKind`, `TurnStopReason`, `SessionAppendDoor`): kode bercabang pada `kind`, bukan pada label tampilan (→ MOD-04, MOD-06).
4. Pemotongan selalu bertanda (`[+N chars]`, "catatan potong") dan label dari pihak lain disanitasi satu baris (→ MOD-07, MOD-19).
5. Kegagalan lunak yang jujur: gagal baca → konteks apa adanya; gagal gerbang → tolak; pengamat tidak pernah memblokir (cocok dengan `emitAgentTurnEvent` yang sudah fail-soft).
6. Spesifikasi dalam README mendahului uji: di `agents-md` README menjanjikan jauh lebih banyak daripada 5 `test()`; jangan memakai README donor sebagai bukti perilaku.
7. Mode kegagalan git/Windows dijadikan angka dan uji, bukan asumsi (12.000 karakter pathspec, 32.767 command line, nama berkutip, HEAD yatim) (→ MOD-13).

Pertanyaan terbuka untuk Main/pemilik:

- Q1. Apakah Native akan bekerja pada proyek di luar Agent Core yang memiliki `AGENTS.md`/`CLAUDE.md` sendiri? Tanpa jawaban ya, MOD-01/02 tetap hanya referensi.
- Q2. Apakah pemilik ingin pengukuran ukuran per sumber (MOD-06) lebih dulu, untuk memutuskan apa yang dikurangi pada `AGENTS.md` dan manifest, sebelum menyentuh bootstrap (MOD-18)?
- Q3. Seberapa sering Native memakai provider dengan batas token keluaran kecil? Jika sering, MOD-04 naik ke urutan pertama.
- Q4. Apakah `write_file` tanpa baca-dulu boleh mulai memberi peringatan (MOD-09), mengingat controller eksternal memakainya dengan pola berbeda-beda?
- Q5. Bagaimana irisan `plugins/code-review` (pekerja lain) menilai skema temuan review? MOD-14 perlu disatukan dengan hasilnya.

Hambatan dan hal yang tidak dibaca: ±1.100 file (barrel, fixture, render UI pane, sidik-jari mesin, name-folding sec-default) tidak dibuka satu per satu; sumber engine donor tidak ada di repo (kontrak tipe ≠ perilaku teruji); ±64% baris `claude-code.d.ts` hanya dipindai nama (UI/render/mount/testing kit); perilaku timeout-to-background pada `start_process` Agent Core tidak diverifikasi; kecepatan/kinerja tidak diukur sesuai arahan.
