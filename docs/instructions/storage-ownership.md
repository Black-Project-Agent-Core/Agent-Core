# Storage ownership

[Mandatory entry](../../AGENTS.md). Global scope/safety still apply. Code-quoted paths are project-root-relative.

## Storage ownership — one purpose, one canonical home

**Koreksi pengguna 2026-10-27: hormati rumah pertama.** `<PROJECT_ROOT>/runtime/skills` adalah rumah Skill existing dan tetap menjadi induk canonical. Folder yang hadir belakangan tidak boleh mengambil alih otoritas atau memindahkan fungsi ke luar rumah lama. Penetapan `bundled-skills` sebagai rumah sumber terpisah pada respons sebelumnya SALAH dan sudah digantikan aturan ini; jangan membuatnya kembali.

**DILARANG KERAS membuat folder baru di lokasi lain untuk tujuan yang sudah memiliki folder dan owner existing.** Sebelum membuat folder, identifikasi tujuan, owner penulis, dan lokasi existing; gunakan lokasi itu. Nama baru, tanggal, versi, nama controller, kemudahan akses, atau istilah seperti `new`, `v2`, `copy`, `backup`, dan `final` bukan alasan untuk membuat rumah penyimpanan paralel. Akses yang tidak tersedia harus dilaporkan; jangan membuat pengganti diam-diam.

- **Peta struktur wajib: [docs/PROJECT-STRUCTURE.md](../PROJECT-STRUCTURE.md).** Sebelum membuat folder, semua agent/controller (Main, Native, external, Raka, dan subagent lain) wajib membaca bagian tujuan/root yang relevan, memeriksa filesystem aktual beserta folder existing dengan fungsi yang sama, lalu memakai owner dan rumah yang sudah ada. Peta adalah indeks lokasi, bukan izin membuat seluruh pola atau folder yang tidak tampak di snapshot. Ketika tujuan baru benar-benar diperlukan oleh task, dokumentasikan owner/lokasi/lifecycle pada peta dan bagian terkait `docs/CODEBASE.md` dalam task yang sama. Jangan membuat peta struktur tandingan.
- Main wajib memasukkan pointer peta, root task, lokasi canonical dan larangan rumah paralel dalam setiap paket delegasi. Raka mengikuti aturan yang sama sesuai `subagents/raka.md`; periksa perubahan partner sebelum menerima hasil. Kewajiban ini berlaku juga ketika agent berjalan melalui host lain; instruksi tertulis tidak membuktikan semua host telah mengeksekusinya.
- **Pemeriksaan otomatis struktur:** `npm run structure:check` memeriksa snapshot pada peta terhadap filesystem; pemeriksaan yang sama juga wajib melalui `npm run path:check` sebelum build. `npm run structure:sync` memperbarui hanya blok snapshot, menolak folder undeclared/alias/duplikat yang dikenali; jangan mengedit blok snapshot manual atau memakai sync untuk melegitimasi rumah tandingan. Deklarasikan tujuan baru pada `directoryIntents` di peta yang sama dengan owner existing sebelum membuat folder. Satu ID tujuan tidak boleh mempunyai dua rumah; nama alternatif tidak mengubah tujuan sebenarnya.
- Shared `create_directory` dan pemindahan direktori melalui `move_file` menjalankan admission sebelum mutasi dan sinkronisasi peta setelah mutasi, sama untuk Native, external dan Raka. Jika sinkronisasi gagal sesudah operasi, pesan `PROJECT_STRUCTURE_UPDATE_FAILED_AFTER_MUTATION` menyatakan side effect sudah terjadi: periksa keadaan sebelum mengulang. Tidak ada grant baru dari deklarasi peta. Shell, editor atau program eksternal tidak di-sandbox oleh pemeriksa ini: semua agent yang memakai jalur itu wajib mematuhi deklarasi yang sama, menjalankan `structure:sync` lalu `structure:check`, dan menuntaskan drift sebelum mengakhiri task. Jangan mengganti tool untuk melewati penolakan admission.
- Semua penyimpanan Skill proyek berada di bawah `<PROJECT_ROOT>/runtime/skills/`. Sumber yang dikembangkan/dipelihara proyek hanya berada di `runtime/skills/capability-packs/<skill-name>/`. Koleksi existing dipindahkan ke dalam rumah lama ini, bukan disalin menjadi rumah kedua. Satu nama Skill memiliki satu rumah sumber; validasi/staging/promosi tetap melalui SkillService.
- Di dalam rumah lama, role adalah `capability-packs` untuk sumber; `catalog`, `revisions`, `.staging`, `packages`, `exports`, `proposals`, dan `tooling` untuk artifact/state terkelola. Role berbeda tetap di bawah induk yang sama; lihat README root existing.
- `catalog/<skill-name>` adalah artifact aktif; `revisions/<skill-name>/staged|history/<digest>` adalah kandidat dan rollback. Salinan terkelola ini memiliki peran berbeda dari sumber. Perubahan, pemindahan, pruning, pensiun (`retire`) dan rollback hanya melalui lifecycle owner existing; dilarang mengedit/menghapusnya langsung di filesystem atau menggantinya dengan junction/hardlink untuk menyeragamkan tampilan folder.
- Dilarang membuat atau menghidupkan kembali rumah alternatif seperti `<PROJECT_ROOT>/bundled-skills`, `skills`, `capability-packs`, `runtime/capability-packs`, `runtime/skill-catalog`, `runtime/skills-v2`, atau folder Skill langsung di root `runtime/skills`. Larangan yang sama berlaku pada nama alternatif lain dengan tujuan identik, meskipun belum dikenali pemeriksa otomatis. Restrukturisasi wajib menghormati induk existing yang lebih dahulu dipakai.
- Subfolder baru untuk Skill baru diperbolehkan di rumah sumber yang benar. Role penyimpanan baru hanya dibuat ketika task memang memerlukan tujuan baru; tetapkan owner, lokasi, pembaca/penulis, dan lifecycle pada dokumentasi existing sebelum membuatnya. Jangan menduplikasi tujuan existing atau membuat registry/engine penyimpanan kedua.
- File lisensi/referensi di dalam paket mandiri, ekspor host yang diminta, dan snapshot immutable yang dikelola owner bukan rumah authoring baru. Jangan melakukan deduplikasi fisik yang merusak packaging, pembacaan artifact-local, provenance, atau rollback.
- Untuk restrukturisasi, petakan konsumen dan bedakan sumber, artifact aktif, kandidat, history, ekspor dan konfigurasi terlebih dahulu. Pertahankan data historis yang unik; tidak ada penghapusan otomatis atau pembuatan folder karantina/backup ad hoc.
- `npm run path:check` juga memeriksa ownership struktur Skill. Folder yang salah harus diperbaiki pada lokasi/owner-nya; jangan melemahkan check, menambah pengecualian nama, atau membuat salinan baru untuk melewatinya. Pemeriksaan ini tidak menggantikan validasi artifact oleh SkillService.
