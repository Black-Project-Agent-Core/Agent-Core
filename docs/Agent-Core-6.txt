### 1. Self-Learning Loop — mekanisme utamanya

**File paling penting:**

```text
E:\Projects\hermes-agent\agent\background_review.py
```

Ini adalah **loop belajar otomatis Hermes yang sebenarnya**. Setelah turn selesai, Hermes dapat membuat fork `AIAgent` terpisah yang membaca snapshot percakapan lalu mengevaluasi:

```text
Percakapan User
      ↓
Hermes mengerjakan task
      ↓
Final response dikirim ke user
      ↓
Trigger learning tercapai?
      ↓
background_review
      ↓
Fork AIAgent terpisah
      ↓
Analisa conversation:
 ├─ user mengoreksi AI?
 ├─ ada workflow baru?
 ├─ ada workaround/fix?
 ├─ skill lama salah?
 ├─ ada preference durable?
 └─ ada pengetahuan reusable?
      ↓
 ┌──────────────┬──────────────┐
 ▼              ▼
Memory        Skills
MEMORY.md     SKILL.md
USER.md       references/
              scripts/
              templates/
```

Yang menarik: komentarnya sendiri secara eksplisit menyebut ini sebagai **`self-improvement loop`**.

Review fork tersebut memang diarahkan untuk aktif mencari:

```text
user corrections
style / tone / verbosity preferences
workflow corrections
non-trivial techniques
fixes
workarounds
debugging paths
outdated skills
durable memory
```

Dan hasilnya bisa menulis lewat:

```text
memory(...)
skill_manage(...)
```

Tanpa mengotori percakapan utama atau prompt-cache utama.

### 2. Trigger otomatisnya

Memory trigger berada di:

```text
E:\Projects\hermes-agent\agent\turn_context.py
```

Function:

```python
_tick_memory_nudge(...)
```

Logikanya:

```text
setiap user turn
    ↓
_turns_since_memory += 1
    ↓
mencapai nudge_interval?
    ↓ yes
background memory review
```

Default source = **10 turn**.

Dan konfigurasi Hermes milikmu sekarang memang:

```yaml
memory:
  memory_enabled: true
  user_profile_enabled: true
  memory_char_limit: 2200
  user_char_limit: 1375
  nudge_interval: 10
```

Jadi **memory auto-review aktif setiap 10 user turn**.

---

Skill trigger ada di:

```text
E:\Projects\hermes-agent\agent\turn_finalizer.py
```

Berbeda dari memory, ini menghitung **tool iterations**:

```text
_iters_since_skill
      ↓
>= _skill_nudge_interval
      ↓
background skill review
```

Konfigurasi aktifmu:

```yaml
skills:
  creation_nudge_interval: 15
```

Artinya sekarang:

```text
Memory learning → setiap 10 user turns
Skill learning  → setiap 15 tool iterations
```

Kalau salah satunya terpenuhi, `turn_finalizer.py` menjalankan:

```python

```

dan itu masuk ke `background_review.py`.

Tugasnya adalah **merawat hasil belajar setelah skill mulai menumpuk**.

| Mekanisme         |         Default |
| ----------------- | --------------: |
| Curator enabled   |          `true` |
| Interval          |          7 hari |
| Minimum idle      |           2 jam |

Alurnya:

```text

      ↓

      ↓
```

Curator tidak langsung delete sembarangan. Skill yang tidak terpakai masuk lifecycle dan **archive bersifat recoverable**.

```text

```

Jadi bukan sekadar CLI command manual; ada housekeeping otomatis.

# 3. Memory Management Hermes

Core built-in memory berada di dua file utama:

```text
E:\Projects\hermes-agent\tools\memory_tool.py
E:\Projects\hermes-agent\tools\memory_tool_store.py
```

Storage aktual:

```text
E:\Projects\hermes\memories\MEMORY.md
E:\Projects\hermes\memories\USER.md
```

Perannya berbeda:

| Store       | Fungsi                                                   |
| ----------- | -------------------------------------------------------- |
| `MEMORY.md` | environment, conventions, durable notes, quirks, lessons |
| `USER.md`   | identitas/preference/style/profile user                  |

Memory mempunyai operasi:

```text
add
replace
remove
batch
```

Batch bersifat **atomic**:

```text
remove old
+
replace existing
+
add new
        ↓
satu transaction logis
        ↓
final size diperiksa
        ↓
baru persist
```

---

## Memory memiliki hard limit

Konfigurasi aktifmu:

```text
MEMORY.md = 2200 chars
USER.md   = 1375 chars
```

Ini sengaja kecil karena memory built-in dimasukkan ke system prompt setiap session.

Kalau penuh, Hermes diarahkan untuk:

```text
consolidate
    ↓
merge overlapping memories
    ↓
remove stale memory
    ↓
add new durable information
```

Bukan terus append tanpa batas.

---

## Memory snapshot dibuat immutable per session

Ini detail arsitektur yang cukup bagus.

Saat session dimulai:

```text
MEMORY.md / USER.md
        ↓
load_from_disk()
        ↓
_system_prompt_snapshot
        ↓
FROZEN
```

Kalau background review menulis memory baru di tengah session:

```text
disk → UPDATED
current system prompt → TIDAK berubah
next session → baru melihat memory baru
```

Tujuannya menjaga **prompt-prefix/cache stability**.

---

## Memory storage punya proteksi yang cukup matang

`memory_tool_store.py` sudah mempunyai:

```text
Windows file locking → msvcrt
Unix locking         → fcntl

atomic writes
duplicate prevention
character budget
batch atomicity
external-edit drift detection
backup on drift
threat/injection scanning
ambiguous-match protection
consolidation retry limit
```

Ada juga guard menarik untuk background learning.

Background review boleh otomatis:

```text
ADD memory
```

tetapi tidak boleh diam-diam melakukan:

```text
REPLACE
REMOVE
```

Untuk destructive/consolidating memory operation, Hermes melakukan:

```text
background review
      ↓
replace/remove requested
      ↓
STAGED
      ↓
/memory pending
      ↓
user approve / reject
```

Jadi self-learning tidak diberikan kebebasan penuh untuk menghapus memory lama tanpa review.
