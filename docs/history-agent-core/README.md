## Evidence boundary

- A filename or archive location is not a completion claim. Each plan's dated execution/closure sections govern the scope it actually proved; consumer-only/deferred proposals remain proposals unless later source and evidence establish adoption.
- Native runtime-deferred sequencing, old GitHub legacy-only boundaries, older version numbers, old roots and host-specific counts describe historical checkpoints. Current Native/provider/chat source and the current-line repository supersede blanket absence/legacy claims.
- Historical `OPEN`, `PENDING`, approval requests, installation steps and test commands do not authorize new work. Follow only current user intent and applicable project rules.
- `runtime/tmp`, backups, donor checkouts and private Memory IDs are original evidence references. Their contents are absent or outside this source-only review; no runtime result was reproduced merely by reading a report.
- Keep completed acceptance closed. Preserve explicit residuals and evidence gaps without converting them into automatic work.
