## 3. Approved AIOS-P1 contract

Add `scripts/verify/verify-workbook.mjs --workbook FILE.xlsx --spec SPEC.json --output NEW_REPORT.json`. This is a direct offline consumer of current workbook artifacts; no credential, model, browser/Office application, LibreOffice conversion, automatic test trigger or new MCP tool is required. Existing read/edit APIs and the answer-string effectiveness evaluator keep their meanings. No broad training or general document-quality claim is made.

**Specification:** strict version 1 JSON containing a supplied workbook SHA-256 and 1-256 uniquely identified rules. Every cell rule names the exact sheet and a single valid A1 coordinate within XLSX bounds. Supported rules are: `sheet-names` (ordered exact names); `cell-value` (explicit string, finite number, boolean or logical blank); `cell-formula` (exact stored formula after removing only one optional leading `=` from the expectation); `cached-result` (explicit stored-cache comparison); and `freeze` (expected frozen row/column splits). Unknown rules/properties, duplicate IDs, empty rule sets, nonfinite numbers and invalid coordinates are specification errors, not silently skipped tests.

No fuzzy matching or rounding is implicit. `cell-value` rejects formula-bearing cells as unavailable rather than treating a cached result as a fresh calculation. `cell-formula` checks syntax-string equality, not mathematical equivalence. Unresolved shared/array formulas, unsupported value types or missing formula caches are unavailable with an exact reason. A deliberately requested `cached-result` comparison is labeled stored-cache equality with `recalculated=false` and freshness not established, even when equal. Blank cells are distinct from zero, false and an empty string; a missing sheet is a failed structural expectation, not a blank cell. Version 1 does not compare charts, pivots, arbitrary styles, date coercions or screen appearance.

**Input handling:** local `.xlsx` only; no URL, `.xls`, `.xlsm`, encrypted workbook or macro execution. Read the workbook from an opened regular-file descriptor into one capped immutable snapshot, checking identity and change before/after. Verify the supplied digest on those exact bytes; the parser must consume that same snapshot, not reopen the pathname. The specification is likewise read with a bounded unchanged-input check. Digest equality is identity evidence, not an authenticated golden answer or proof the operator's expectations are correct.

**Resource limits:** workbook compressed bytes at most 10 MiB; specification at most 2 MiB; at most 4,096 ZIP entries, 16 MiB per member and 64 MiB total actual expanded bytes. Validate archive paths/types, encryption and compression before parsing, and enforce streamed actual decompression limits in addition to central-directory declarations. Refuse macro parts and external-workbook references for this initial profile; never fetch relationships or run embedded content. Use at most 256 rules and avoid sheet-wide row/column enumeration; output at most 1 MiB. Time-bounded owned-child execution may be used for parsing if required, but no hostile-code sandbox claim or unbounded provider fallback is permitted.

**Report:** include algorithm/spec revision, input and specification digests, inspected sheet/rule identities, per-rule `pass|fail|unavailable` with reason codes, aggregate counts and a bounded evidence record. Default output records observed value types/digests rather than dumping workbook contents. Unsupported data remains visible. Overall `pass` requires a valid nonempty specification and every rule passing; any unavailable rule makes overall unavailable, otherwise a mismatch makes fail. CLI exit codes: 0 all checks pass, 1 completed comparison with mismatch, 2 invalid/unavailable input or incomplete checking. Write a NEW report exclusively, then verify its bytes; never overwrite the workbook/specification or auto-correct a failed cell.

The result proves only the selected stored-artifact assertions against the supplied expectations. It does not prove formula recomputation, financial correctness, visual quality, task completeness outside the rule set, causal agent improvement or permission to deploy. `memoryPersisted`, `mutatesWorkbook`, `runsFormulas` and `automaticApproval` remain false.

The CLI accepts `--workbook FILE.xlsx --spec SPEC.json --output NEW_REPORT.json`. Specification version 1 requires a supplied SHA-256 and 1–256 uniquely identified rules: ordered sheet names, typed cell values, exact formula text, explicit cached-result comparison, and frozen row/column splits. Unknown fields/rules, invalid coordinates and nonfinite values are refused. Missing sheets fail; formula-as-value, unsupported value types, shared/array/merged scalar ambiguity and missing caches remain unavailable. Empty rules never pass. Cached results carry `recalculated=false` and `cacheFreshness=not-established`.

Local inputs are read through bounded same-descriptor snapshots with path/link/identity/size/change checks. Limits: workbook 10 MiB, specification 2 MiB, 4,096 ZIP entries, 16 MiB per member, 64 MiB total actual expansion, and 1 MiB report. Actual streamed sizes and CRCs are checked; canonical member paths, duplicate names, macros, external relationships and entity declarations are refused. Admitted bytes are repacked without compression before ExcelJS consumes them, preventing a second attacker-controlled inflate. XML/worksheet allocation limits additionally bound nodes, row slots, cell slots and merged expansion. Unsupported or over-budget workbooks return unavailable, not a guessed comparison.

Review fixtures showed that ExcelJS's generic formula-value projection omits falsy cached values; the dedicated result getter now preserves zero and false. Strict XML number/boolean validation also prevents parser coercion such as `0garbage` becoming zero. Duplicate cells, invalid pane data and excessive sparse allocations are rejected before library evaluation. These corrections and their initially failing tests are retained in the evidence folder.

The parser runs in an owned worker thread with a 30-second deadline and V8 heap limits (256 MiB old generation, 32 MiB young generation); this is resource control, not a hostile-code sandbox or total process-memory guarantee. Every CLI run closes the worker. Inputs are rechecked for drift, a new report is written exclusively and read back from its descriptor, and stdout includes its byte digest. Exit codes are 0=all selected assertions pass, 1=completed mismatch, 2=unavailable/error. No workbook/specification is overwritten or repaired.
