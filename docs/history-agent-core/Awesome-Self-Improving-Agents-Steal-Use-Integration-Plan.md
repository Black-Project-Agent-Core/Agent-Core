## 5. ASI-P2 — fixed-protocol trajectory, transfer and cost report

**Source basis:** `evaluation.tex` paragraphs on fixed budgets, held-out transfer, resource/supervision accounting and judge independence; `Definitions.tex` distinguishes persistent scaffold from transient context. These are requirements to operationalize, not a supplied implementation.

**Proposed owners:** pure `src/learning/retrieval-series.ts`; a `series` mode in the explicit analysis CLI; `tests/learning-retrieval-series.test.ts`. No timer, telemetry database or automatically generated cohort. The operator supplies a bounded run manifest (for example at most 100 references), ordered iteration/seed/checkpoint identities and a reviewed split/protocol manifest.

**Comparability contract:** same corpus, cohort, topK, evaluator/verifier and common baseline identity within each series. Recompute/check each input report. A parent-relative delta cannot silently be ranked against a different parent. Different protocols are separate series, not coerced into one leaderboard. Split membership must be explicit and nonoverlapping; unknown training exposure remains `not-established`, never “held-out passed”. Test a supplied overlap as a negative control.

**Report semantics:** list every supplied checkpoint, baseline and candidate absolute hit rate, paired regressions/retention, and observed delta. Report seed count and dispersion only for genuinely comparable independent runs; do not infer statistical significance from the sample minimum. Distinguish attempted, invalid, failed, incomplete and evaluable runs so a final peak does not hide failures. User-defined resource budgets are reporting dimensions, not permission to run more work.

Costs must be explicitly provided with provenance: wall-clock time, tool calls, input/output tokens when measured, evaluator cost separately from task cost, and human intervention count/modality. Missing measurements stay unknown; no guessed dollar amounts or fabricated zero overhead. Do not automatically read production tracker, private traces or account billing. An optional recorded disk/write budget should guard the operator's experiment design, not create a background cleanup agent.

**Implementation after selection:**
1. Fix a manifest/protocol schema and a read-only consumer before adding aggregate code. Require at least two distinct supplied reports for trajectory output; one report returns a clearly labeled single checkpoint.
2. Add negative fixtures for changed baselines/evaluator/data, overlapping splits, repeated report IDs, missing stages/costs and nonmonotone cumulative counters. The list of attempted runs is supplied evidence, not provably exhaustive history.
3. Compute bounded trajectory/retention/cost tables; surface unknowns, out-of-budget observations and incompatible groups. Never silently select only the winner or launch a follow-up evaluation.
4. Verify independently by fixture arithmetic; preserve input hashes, old artifacts and the current five Learning actions. Keep human review mandatory for any claim/capture/activation.
5. Document exact limitations and update CODEBASE/memory plus selected patch intent. Without real run manifests, ship only after the user chooses this feature; do not synthesize a production-improvement result.

**Acceptance:** a high final score cannot erase earlier failed runs or regressions; incomparable revisions are separated; no held-out or cost claim is invented; the report remains offline and non-mutating. This is an optional extension, not a blocker for ASI-P1 or current Agent Core operation.

## 6. ASI-P3 — coverage-preserving shortlist from inspected GEPA source

**Primary implementation:** `gepa-ai/gepa` commit `d771eb21b5dd3228bc3f567293d2ccfc423fc900`, `src/gepa/gepa_utils.py::{is_dominated,remove_dominated_programs,find_dominator_programs,select_program_candidate_from_pareto_front}` and `src/gepa/strategies/candidate_selector.py`. State definitions and selector tests were inspected as supporting contract evidence; those full suites were not run.

**Exact mechanism:** GEPA maps individual validation instances to candidate sets at their best score. Its helper iteratively removes candidates whose front memberships are already covered by other remaining candidates, processing candidates by aggregate score. Its selector can then sample weighted by surviving front frequency. This is **coverage-preserving redundancy removal**; it must not be mislabeled as proof of conventional all-objective Pareto domination by one candidate.

**Observed probe:** the unchanged pinned utility ran via Python stdlib only. Four test fronts retained coverage after reducing three equal-aggregate candidates to survivors 0 and 1; seeded sampling reproduced and empty-map pruning returned an empty map. This demonstrates the helper semantics, not a benchmark gain or permission to run the GEPA optimizer.

**Proposed native scope:** port only the small coverage-preservation operation into `src/learning/retrieval-portfolio.ts`; expose `frontier` mode in the existing proposed analysis CLI. Input is an explicitly supplied, comparable batch of verified hit-at-K profiles, not generated prompts. Output a deterministic shortlist with per-query reasons and coverage-loss checks. Keep complete inputs and excluded candidates in the audit output.

Do not port `GEPAState`, reflective mutation, model calls, epsilon-greedy exploration, unbounded evolution or automatic deployment. For binary retrieval scores, all-candidate misses are `uncovered`, not an achievement merely because zero scores tie for best. Bound candidates/queries before allocating the matrix and make tie-break ordering stable by report identity. Candidate score validity and report completeness remain distinct from shortlist membership.

**Implementation after selection:**
1. Preserve GEPA's MIT copyright/permission notice for a substantial port and record the exact upstream commit in `THIRD_PARTY_NOTICES.md`. The Awesome catalog license does not substitute for it.
2. Write pure tests for the audited four-front example, unique specialists, redundant equal-score candidates, stable ties, empty input, all-zero cases and invalid/out-of-range candidate IDs. Include a case where union coverage survives but no single candidate dominates the removed one.
3. Port the reduction with explicit count/type/finite-value validation instead of Python assertions as a production input boundary. Deterministic shortlist output is the default; no random automatic selection is needed.
4. Compare source-helper results on valid fixtures, verify each previously covered instance retains a survivor, and report all uncovered cases. A shortlist is not a deployment recommendation or proof of superiority on held-out tasks.
5. Wire only the explicitly selected offline analysis mode; no live Memory/Grafel mutation, no model call, no new MCP tool. Update docs/memory and selected patch intent.

**Acceptance:** matrix coverage never silently decreases; unique specialists remain; duplicates/ties are reproducible; all-zero inputs do not become winning claims; mixed cohort/evaluator/baseline results are refused or separated. An invalid subset cannot silently fall back to a highest aggregate candidate.

**Dependencies:** ASI-P1's validated case profile or an equivalent explicitly reviewed profile contract. P6 completeness verification is preferred when selected. Do not install the Python GEPA package to perform this small native adaptation.
