## Implemented behavior

- Newly interrupted checkpointed chat turns receive one asynchronous, sequential startup recovery pass through existing `resumeTurn`. Startup does not await model inference. Previously paused/resumable turns are not blindly retried on every restart.
- Current DTC checkpoint identity, source/artifact integrity, authorization, tool contracts, cancellation and consumed budgets remain authoritative. Dispatching mutations with unknown outcomes remain paused; a revision-bound reason is stored without rewriting a newer claim/checkpoint or cancelled turn.
- Chat-level `assistant.final` is emitted only after the assistant row is committed. The emitted text and returned response are read from the canonical persisted chat projection, including storage sanitation. Direct controller execution keeps its existing terminal event contract.
- Observer disconnection cannot cancel a committed response. Notice-attribution failures are diagnosed separately after commit. Resumed work preserves separate Learning and job-verification metadata, including a finalized work result whose Learning failed.
- UI uses readable progress and persistent saved/failed/stopped/interrupted/recovery states. Paused recovery blocks a new send and offers the existing cancel action. The UI type now includes the backend's existing `resumable` state.
- Endpoints, NDJSON envelope shape, database schema, tool grants and provider scheduler are retained. Pending minor Native reliability and major browser-engine-removal release intents are recorded; no version is applied or published.
