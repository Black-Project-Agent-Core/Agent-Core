## Masalah dan tujuan
Pengguna memerintahkan (`/goal`, 2026-10-27) agar ketiga folder referensi dipelajari sedalam mungkin dan setiap bagian yang dapat memperkuat Agent Core dicari, lalu hasilnya menjadi satu proposal upgrade. Dokumen ini adalah proposal itu. Isinya **apa** yang layak diambil, **di mana** menguntungkan Agent Core, dan **bagian mana** yang diperkuat. Tidak ada yang dikerjakan sebelum pengguna memutuskan tiap paket.

Dua hal yang membentuk isi:
1. **Studi lama atas `claude-code` sudah ada** dan sebagian sudah diimplementasikan (CC-P1 sampai CC-P4 pada 2026-09, lalu lima usulan pada 2026-10-27: Stop sampai ke tool, accounting konteks, kompaksi durable, adapter Skill plugin Claude, panel perubahan task; lihat `docs/history-agent-core/Claude-Code-Steal-Use-Integration-Plan.md` dan `Peluang-Upgrade-Agent-Core-dari-Claude-Code.md`). Dokumen ini tidak mengusulkan ulang yang sudah dipakai. Dua repo lain belum pernah dikaji.
2. **Temuan paling bernilai bukan fitur baru, melainkan cacat pada hasil adopsi sebelumnya dan celah keselamatan host Windows.** Beberapa sudah saya buktikan langsung di source (ditandai "terverifikasi Main"). Fitur baru dibatasi karena dua kendala nyata: anggaran manifest tool MCP hampir habis (130.965 dari 131.072 byte) dan teks selalu-dimuat (`AGENTS.md` 84 KB) sudah menjadi masalah. Maka hampir semua paket berbentuk perbaikan internal, skrip baca-saja, tes, atau konten Skill on-demand; **tidak ada paket yang memerlukan skema tool MCP baru**.

## UP-01. Scanner keamanan `changed_source`: benar, jujur, teruji
- **Teramati (terverifikasi):** lihat daftar di Bukti. Cacat aktif yang nyata ada tiga: `resolved` palsu untuk file yang dilewati, aturan berisik (`exec(` dan TLS), dan nol tes. Badan hasil sudah memuat `skipped` dan `filesScanned`; label `clean` hanya menyesatkan pada Activity Tracker (`code-intelligence-tools.ts:439`). Pemotongan 128 file tidak terjangkau lewat tool (skema `.max(128)`), jadi butir pagar di bawah bersifat defensif, bukan perbaikan cacat aktif. Pemeriksa independen juga memastikan bahwa penjaga ReDoS aturan proyek (`:76`) meloloskan alternasi tumpang-tindih seperti `(a|aa)+$` (pola itu pada `"a"*32+"b"` memakan 284 ms dan tumbuh eksponensial) dan bahwa lifecycle (`:41-42`, `:105-109`) hanya hidup di memori proses (maksimal 64 lingkup, hilang saat restart).
- **Donor:** `claude-plugins-official/plugins/security-guidance` dan `claude-security` (aturan dengan gerbang ekstensi dan pengecualian aman, sidik jari temuan berbasis konteks, laporan cakupan, validasi temuan), `claude-code/plugins/security-guidance`. Hanya mekanisme; tanpa salinan.
- **Perubahan terkecil:** (1) lookbehind atau gerbang pada `exec`/`eval`, TLS hanya bila nilainya `0`; (2) `resolved` hanya untuk file yang benar-benar dipindai ulang (cacat aktif), label Tracker `partial` bila ada file dilewati, dan pagar defensif `filesDropped`/`truncated` dengan `filesRequested` dihitung sebelum `slice` (tidak terjangkau selama skema membatasi 128); (3) kunci temuan = id aturan + file + hash ±3 baris ternormalisasi; (4) kira-kira 12 aturan terkurasi dengan `include` per ekstensi (sink DOM, `${{ github.event.* }}` pada `run:`, AES-ECB, perbandingan tanda tangan non-konstan-waktu, deserialisasi varian), ID `AC.SECURITY.*` stabil; (5) bidang `introducedByChange` dari `git diff -U0`; (6) `tests/changed-source-security.test.ts` pertama: kasus positif dan negatif per aturan, batas 128, file dilewati, pergeseran baris, ReDoS, serta satu kontrol negatif bawaan.
- **Tambahan dari putaran penutup terakhir (pekerja):** nama berkas berawalan `..` (mis. `..cache`) dianggap lolos dari akar dan membatalkan seluruh pemindaian (GCG-04, terukur pekerja); notebook `.ipynb` dipindai per sel kode (GCG-06); klasifikasi "diperkenalkan" vs "sudah ada" lewat `git show HEAD` melengkapi `introducedByChange` (GCG-05); kontrak cakupan: penanda potong, daftar `limits`, `nothing-scanned`, dan satu-temuan-per-aturan-per-baris yang diberitahukan (GCG-07).
- **Temuan terkait:** CCP-01 sampai 04, CCP-15, OFA-01 sampai 03, GCB-01 sampai 03, 05 sampai 08, GCD-03, GCG-04 sampai 07, KWP-08.
- **Acceptance:** tes baru lulus; `npm run build` dan path policy lulus; hasil lama tetap terbaca (bidang tambahan saja); tidak ada skema tool baru; changeset minor.
- **Risiko / flip:** controller yang mengonsumsi `clean` perlu tahu semantik `partial`. Batalkan penambahan aturan yang menghasilkan false positive lebih dari ambang pada `src` Agent Core sendiri.

- **Perubahan terkecil:** (a) `kill_process` menolak PID Agent Core sendiri, proses induk, dan pohon proses sendiri, dan skemanya memvalidasi `Number.isInteger(pid) && pid > 0` (CHB-01); (b) `ownerTaskId` opsional pada ledger proses dan laporan Stop yang menyebut proses milik task yang masih berjalan, tanpa penghentian otomatis (MOD-10); (c) `canonicalPathKey()` tunggal untuk pemeriksaan jalur terlindungi, terutama bagi pemanggil leksikal-saja yang disebut di atas (GCA-03); (d) penjaga penghapusan katastropik refusal-only pada jalur shell (`command-manager.ts` dan `blockedCommands`; CHG-05), **keputusan D1**; (e) korpus uji bypass `command-manager` ditulis lebih dulu, baru logika diubah (CHG-04, dengan koreksi false positive dari CHB-12); (f) decoder streaming UTF-8, penghapusan ANSI dan `NO_COLOR`, penjelasan kode keluar NTSTATUS (CHB-02, CHG-16, CHB-10); (g) audit "penjaga yang gagal harus menolak": setiap try/catch pada penjaga diperiksa dan diberi tes (CHG-19); (h) catatan penasihat untuk target persistensi eksekusi (profil PowerShell, Startup, `.git/hooks`, kunci Run) (CHB-06); (i) tenggat, stdin tertutup sebelum kill, deteksi menunggu input pada proses latar (CHG-18); (j) jalur Windows berbahaya: namespace NT, UNC/NTLM, junction, path panjang (CHG-08); (k) `command-manager.ts` belum punya satu pun tes, daftar blokirnya tidak menormalkan `.exe` (`reg.exe` tidak cocok entri `reg`) dan baris baru bukan pemisah perintah (pekerja, dari uji string dan pembacaan kode; daftar ini hanya penasihat) (GCH-03).
- **Acceptance:** tes tabel per butir; `kill_process` pada PID sendiri mengembalikan galat terstruktur; tidak ada skema tool baru (galat pada payload yang ada); tidak menaikkan grant (hanya menolak).
- **Risiko:** false positive pada penjaga hapus menghalangi pekerjaan sah; direktif `AGENTS.md` "tidak perlu minta izin" sebagai konteks: lihat D1.

## UP-04. Integritas berkas dan git di host Windows
- **Teramati (terverifikasi):** `text.ts:55-64` hanya BOM UTF-16LE; sebuah file Windows-1252 yang dibaca sebagai UTF-8 lalu ditulis ulang kehilangan byte; Agent Core tidak memvalidasi `base`/`head` di `change-review.ts:85-87` (provider Grafel dipanggil lebih dulu pada rute `code_surface impact` dan penolakannya tidak terverifikasi; tool dideklarasikan `readOnlyHint: true` padahal opsi seperti `--output=` menulis berkas); git tanpa `core.fsmonitor=false` di tujuh pemanggil lain (`change-review.ts:66`, `graph-observability.ts:293`, `workflows/service.ts:72`, `workspace-resolver.ts:163`, `memory/repository-identity.ts:14`, `memory/provenance.ts:97`, `semantic-ide/workspace-policy.ts:29,75`). **Terverifikasi pemeriksa independen:** `workspace-fingerprint.mjs` memotong bukti ke 256 jalur tanpa tanda sehingga `compare` bisa melaporkan `resolved` palsu; `noiseClass` hanya sebagian (`package-lock.json`, `*.generated.ts`, `.d.ts`, `.pb.go` berlabel `source`); `task-changes.ts` mempunyai empat cacat kecil yang terverifikasi (tab dalam nama jalur pada numstat `:241`, tanpa `--ignore-submodules` `:233,239`, deadline tidak berlaku untuk bagian external `:229`, tanpa `LC_ALL`), sedangkan HEAD yatim adalah degradasi senyap yang terdokumentasi; `repository-identity.ts:72-78` meng-hash ejaan mentah URL `origin`.
