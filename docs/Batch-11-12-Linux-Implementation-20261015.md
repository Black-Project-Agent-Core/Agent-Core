## Batch 12: #27 current synthesis dependency eligibility

Current project-synthesis eligibility is shared in the existing Memory `project-synthesis.ts`, with dependency resolution and exact snapshot ownership in `MemoryService`. Current controller recall and normal search use the same bounded policy before semantic eligibility/ranking. Eligibility precedes temporal and supersession selection as well as ranking: rejected synthesis links cannot suppress ordinary records. The eligible candidate universe is also the universe for fusion/neighbors. Unvalidated authority/bootstrap projections withhold project-synthesis, and partial eligibility feeds the existing packet coverage as unknown. Pinned synthesis is not exempt; ordinary pinned records retain their existing rules.

The internal `MemorySearchHostContext` uses host-owned ControllerScope, a current-scope assertion, optional AbortSignal/absolute epoch deadline and aggregate summary callback. MCP registration reuses the existing scope resolver. Normal search selects only a native host task or the captured external invocation's bound task. Ordinary controller context forwards the authenticated owner and reuses active task/workspace validation. Public model arguments do not become scope authority. Missing/ambiguous/mismatched scope withholds only the affected synthesis, not ordinary Memory.

Each eligibility request has one cache and a maximum of 32 distinct project-synthesis dependency-graph resolutions (including nested synthesis), an absolute 15-second ceiling or shorter caller remainder, zero automatic retries and ancestry checks before awaiting cached promises. The 32-key cap is shared across candidates and nested synthesis; it is not a cap on physical reads or inherited episode/event/manifest evidence-lineage validation. That existing owner is unchanged. Timeout/abort stops admission of late results; it does not claim underlying I/O was cancelled. After dependency timeout, controller ordinary recall uses its already-read snapshot and normal search skips advisory touch, avoiding an additional wait behind abandoned dependency I/O. Scope/revision/dependency snapshot drift before delivery withholds synthesis as unknown. Current/stale/unknown remain separate states. Exact reads, historical expansion and canonical history keep their own contracts.

Aggregate checked/omitted/completeness/reason codes flow through the existing retrieval ledger and diagnostics. Context evidence gaps expose summary only, not dependency body/ref/path or private ancestry. `memory_search` still returns an array. No auto-refresh, source mutation, new graph/store/runtime, donor package, model, adapter or public schema was added.

Owners: `SubProject/agent-core-memory/src/memory/{project-synthesis,controller-session,service,retrieval-ledger}.ts` and package exports; `src/mcp/{server,memory-tools,memory-experience-tools}.ts`; existing external context owner above; `src/memory/service.ts` retains the legacy host search return type while accepting the optional internal context passed to the active engine.
