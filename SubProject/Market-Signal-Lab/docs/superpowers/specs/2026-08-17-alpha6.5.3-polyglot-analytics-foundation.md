# Alpha 6.5.3 — Polyglot Analytics Foundation Design Specification

## Purpose

Alpha 6.5.3 introduces Rust into Market Signal Lab only where the current source already contains deterministic numerical analytics that benefit from a native high-performance worker. This is not a rewrite of MSL. Go remains the application host and stable reference implementation.

## Current-language baseline

The audited Alpha 6.5.2.1 source uses:

- Go for application services, Envato connector, Market Autopilot, analytics, consensus, ranking, storage, HTTP/SSE, security, telemetry, and most tests.
- Vanilla JavaScript for the browser UI and Browser Capture Companion.
- HTML/CSS for presentation.
- Python only for responsive/visual QA scripts.
- Shell only for verification helpers.
- No Rust and no C/C++ in production source.

## Architecture decision

MSL adopts a **Core + Worker Engines** architecture.

```text
Market Signal Lab.exe (Go)
        │
        ├── scanner / HTTP / storage / telemetry / security (Go)
        │
        └── AnalyticsEngine contract
              ├── go-native   (stable/reference/default)
              ├── rust-native (experimental production worker)
              └── shadow      (Go published result + Rust parity verification)
```

Rust runs as a separate process and communicates through versioned NDJSON over stdin/stdout. No FFI is introduced in this version.

## Rust pilot scope

Rust may replace only the numerical kernels behind these existing capabilities:

1. Cross-surface distribution similarity.
2. Ranking volatility computation.
3. Observed selection probability computation.

Go continues to own:

- Market identity and domain IDs.
- timestamps and evidence stages.
- score provenance persistence.
- context comparability and capture orchestration.
- repository/storage access.
- market-data ingestion.
- all credentials and source-policy logic.

## Engine modes

### Go Native

Default and stable. MSL behaves as before even if the Rust worker is absent.

### Rust Native

Numerical kernel calls go to the Rust worker. Any worker failure automatically falls back to Go and records diagnostics.

### Shadow Verification

The same normalized numerical input goes to Go and Rust. Go remains the published result. Rust is used only for parity verification. A parity mismatch never changes persisted market output.

## IPC protocol

Protocol name: `msl-analytics/1`.

Requests and responses carry:

- protocol version;
- unique request ID;
- operation name;
- normalized numerical input/result;
- engine name/version;
- execution duration;
- structured error code when applicable.

The worker receives no token, Authorization header, cookie, browser storage, account information, raw HTML, raw API body, or direct storage path.

## Failure model

- Missing Rust worker: Go remains usable.
- Rust timeout/crash: fallback to Go.
- Three Rust failures within sixty seconds: circuit opens for sixty seconds.
- Shadow mismatch: mark Rust degraded and keep Go result.
- Protocol mismatch: Rust is unavailable until compatible worker is installed.

## Parity tolerances

- Distribution similarity: absolute delta ≤ `1e-6`.
- Ranking volatility numeric fields: absolute delta ≤ `1e-6`; labels exact.
- Selection probability score/weights: absolute delta ≤ `1e-9`; counts exact.

## Diagnostics

Settings receives a Compute Engine section showing:

- active engine mode;
- Go health;
- Rust health;
- protocol version;
- last parity result and delta;
- fallback count;
- circuit state;
- last safe worker error;
- Run Diagnostics action.

Diagnostics are bilingual English/Indonesia and do not expose credentials.

## Packaging

Windows release layout:

```text
Market Signal Lab/
├── Market Signal Lab.exe
├── engines/rust/msl-analytics-rust.exe
├── browser-companion/
└── README.md
```

Rust does not need to be installed on the user's computer.

## Benchmark policy

Performance is measured, not assumed. Deterministic 10K, 100K, and 1M-observation corpora compare Go and Rust for execution time, throughput, startup overhead, p50/p95 operation latency, and worker memory where available. Benchmark results do not automatically make Rust the default engine.

## Deliberately deferred

- C++ worker implementation.
- Python production runtime.
- Rust scanner/network/storage rewrites.
- Market Flow & Cohort features.
- Trend State, Historical Echo, Seasonality, and Probability Calibration.

C++ enters only if later profiling identifies a concrete hotspot that Rust cannot solve efficiently enough. Python remains a research/QA language until the Backtesting & Probability Calibration phase.

## Repository/documentation policy

README remains evergreen product documentation. Version-specific features, bug fixes, known issues, compatibility notes, binaries, and detailed QA belong in GitHub Releases and CHANGELOG. Specs/plans/QA remain under `docs/`.
